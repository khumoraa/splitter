# Сканирование чека: аудит и дизайн-спецификация

Ветка `feature/scan-receipt` (от `feature/profile-settings`). Expo Go SDK 57.

## 1. Что есть / что сломано / чего нет (до переработки)

| Область | Состояние |
|---|---|
| Вход | Кнопка на главной сразу открывает камеру. Ручного ввода нет, галереи для чека нет (только камера), нет пути «без AI» |
| Расход AI | Нет лимитов на пользователя, нет кэша, нет идемпотентности: двойное нажатие = два платных вызова, повтор того же фото = ещё вызов |
| Вызовы Gemini | Перебор ~10 моделей и 2 версий API (большая часть отключена Google), до десятков запросов на один чек; `GEMINI_MODEL_PARSE` в `.env` **не задан** (в задании сказано, что задан) — по умолчанию в коде `gemini-2.5-flash`, которой нет у Google |
| Схема ответа | Свободный JSON, разбор «на глаз»; налог/чаевые/скидка идут как «позиции» с `kind`; нет даты, заведения, уверенности, итога чека; нет сверки итога |
| Проверка входа | Только `mimeType`/`data` присутствуют: нет проверки magic bytes, размера, разрешения, пустых снимков |
| Ошибки | 502/503 с английским текстом, без кодов |
| Mock | `ALLOW_MOCK_OCR=1` (по заданию должно быть `ALLOW_MOCK_SCAN=true`) |
| Клиент | Камера без рамки/подсказок/вспышки, фото сжимается до 1280 px (JPEG 0.45), результат сразу идёт на выбор участников — **редактирования позиций до «участников» нет**, правка есть только на экране распределения; нет предпросмотра/поворота/обрезки; «вечная крутилка» (120 с), отмены нет; черновика нет |
| Деньги | Модуль в копейках есть (`money.ts`), но результат скана хранится числами с плавающей точкой |
| Ручное создание | `POST /sessions` есть, но без валидации (`serviceFee`/`total` из тела как есть) |
| Фото на сервере | Не сохраняется (только в памяти) — это правильно |

## 2. Решения

- **Один платный запрос на чек**: одна модель (`GEMINI_MODEL_PARSE`, по умолчанию `gemini-3.5-flash`), одна версия API, строгий JSON (`responseMimeType: application/json`), `maxOutputTokens` ограничен, схема проверяется `zod`. Повтор не более одного раза и только при сетевой ошибке/таймауте.
- **Квота**: скользящие окна 24 ч и 30 суток, по умолчанию 10 и 100 (`SCAN_LIMIT_DAILY`, `SCAN_LIMIT_MONTHLY`). В квоту входят вызовы, дошедшие до модели (успех, «не чек», нечитаемый ответ); не входят: невалидный ввод, ошибки до модели, недоступность AI, попадания в кэш и идемпотентные повторы.
- **Кэш**: по SHA‑256 загруженных байт (клиент приводит снимок к одному виду: ≤1280 px, JPEG), на пользователя (чужие чеки не отдаются), `SCAN_CACHE_DAYS=30`. Хранится **только результат разбора** (JSON) и хэш; **фото нигде не сохраняется** (обрабатывается в памяти), потому что для кэша достаточно хэша, а хранение фото — риск приватности без выгоды.
- **Идемпотентность**: заголовок `Idempotency-Key`; повтор с тем же ключом возвращает сохранённый результат и ту же сессию без нового вызова; параллельный дубль → 409 `REQUEST_IN_PROGRESS`.
- **Данные**: одна таблица `ScanRequest` (миграция обратимая, см. план в сообщении), без персональных данных чека кроме разобранного JSON, который обнуляется через `SCAN_CACHE_DAYS`.
- **Налог/чаевые/сервис/скидка** — отдельные поля ответа, а не «позиции»; в существующий поток распределения они передаются как позиции с `kind` и по умолчанию делятся поровну между всеми участниками (пропорциональное деление — отдельное решение).
- **Ручной ввод — равноправный путь**: тот же экран проверки, сессия создаётся только на шаге «Итоги» (`POST /sessions` без AI и без квоты), поэтому ручной ввод работает офлайн до последнего шага.

## 3. Экраны и состояния

```
Новый чек (/tabs/new-receipt)  ← кнопка на главной
 ├─ Сфотографировать → Камера (рамка, подсказки, вспышка, спуск, галерея, закрыть)
 │       → Предпросмотр (Переснять / Повернуть / Использовать; «потратит 1 распознавание»)
 │       → Обработка (Загружаем → Читаем чек → Проверяем суммы; Отмена; таймаут)
 ├─ Выбрать из галереи → Предпросмотр → Обработка
 └─ Ввести вручную (бесплатно, без AI) → Ручной ввод
Результат → Проверка чека (/tabs/receipt-review): шапка, позиции (правка на месте, степпер, удаление, добавить),
            налог/чаевые/скидка (суммой или %), сверка с итогом чека, «Далее» → участники → распределение → итоги
```
Состояния: загрузка (скелетон/индикатор), ошибка с кодом → понятный текст + «Повторить» + всегда «Ввести вручную», офлайн (баннер; доступны только ручной ввод и черновик), лимит исчерпан (карточки AI заблокированы с объяснением и временем сброса).

Токены/темы/доступность — как в `docs/profile-redesign.md` (палитры `tokens.ts`, зоны ≥44 pt, WCAG AA, Reduce Motion, Dynamic Type). Деньги — целые минимальные единицы (`money.ts`), форматирование по валюте.

## 4. Коды ошибок API

`INVALID_IMAGE` (422, `reason`: UNSUPPORTED_TYPE | TOO_SMALL | BLANK | CORRUPT), `IMAGE_TOO_LARGE` (413), `QUOTA_EXCEEDED` (429, `resetAt`, `quota`), `AI_UNAVAILABLE` (503), `NOT_A_RECEIPT` (422), `PARSE_FAILED` (502), `REQUEST_IN_PROGRESS` (409). Сообщения для пользователя формирует клиент по коду.
